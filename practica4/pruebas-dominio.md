# Ejercicio 1.5: Pruebas de Restricciones de Dominio

Los 10 casos se ejecutaron directamente sobre `citas_medicas_p4` en `postgres_laboratorio` (PostgreSQL 15):

| # | Tipo | Operación intentada | Resultado esperado | Mensaje real del gestor | Regla protegida |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `NOT NULL` | `INSERT INTO paciente (nss, nombre, unidad_medica_adscripcion) VALUES ('12345678901', NULL, 'HGZ No. 24');` | Rechazo por nulo en `nombre` | `ERROR: null value in column "nombre" of relation "paciente" violates not-null constraint` | Todo paciente registrado debe tener nombre. |
| 2 | `DEFAULT` | `INSERT INTO paciente (nss, nombre, unidad_medica_adscripcion) VALUES ('12345678901', 'Prueba Default', 'HGZ No. 24');` | Inserta con `estatus_vigencia = TRUE` | `INSERT 0 1` (`estatus_vigencia = t`) | Un paciente nuevo inicia vigente por defecto. |
| 3 | `DEFAULT` + `NOT NULL` | `INSERT INTO paciente (nss, nombre, estatus_vigencia, unidad_medica_adscripcion) VALUES ('12345678902', 'Prueba Null Default', NULL, 'HGZ No. 24');` | Rechazo por `NULL` explícito | `ERROR: null value in column "estatus_vigencia" of relation "paciente" violates not-null constraint` | El estado de vigencia nunca puede quedar indefinido. |
| 4 | `UNIQUE` simple | `INSERT INTO estudio (nombre_estudio, indicaciones_previas) VALUES ('Química Sanguínea 6 Elementos', 'Duplicado');` | Rechazo por nombre duplicado | `ERROR: duplicate key value violates unique constraint "uq_nombre_estudio"` | No pueden existir dos estudios con el mismo nombre. |
| 5 | `UNIQUE` compuesta | `INSERT INTO resultado (valor_obtenido, id_cita, id_estudio) VALUES ('99.0', 1, 1);` | Rechazo por `(id_cita, id_estudio)` duplicado | `ERROR: duplicate key value violates unique constraint "uq_resultado_cita_estudio"` | Cada estudio de una cita admite un único resultado. |
| 6 | `CHECK` de rango | `INSERT INTO prueba_sangre (id_estudio, tipo_tubo, color_tapon, ayuno_horas) VALUES (999, 'Tubo EDTA', 'Lila', 30);` | Rechazo por `ayuno_horas > 24` | `ERROR: new row for relation "prueba_sangre" violates check constraint "chk_ayuno_horas"` | El ayuno clínico debe estar entre 0 y 24 horas. |
| 7 | `CHECK` de formato (`dom_nss`) | `INSERT INTO paciente (nss, nombre, unidad_medica_adscripcion) VALUES ('NSS1234567', 'Formato Malo', 'UMF No. 10');` | Rechazo por letras en NSS | `ERROR: value for domain dom_nss violates check constraint "dom_nss_check"` | El NSS solo acepta 10 u 11 dígitos numéricos. |
| 8 | `CHECK` de formato (`dom_folio_orden`) | `INSERT INTO orden_medica (folio_orden, fecha_cita_medico, medico_emisor, nss_paciente) VALUES ('FOLIO-1', '2026-12-01', 'Dr. Prueba', '11000000001');` | Rechazo por formato inválido | `ERROR: value for domain dom_folio_orden violates check constraint "dom_folio_orden_check"` | Todo folio debe seguir el patrón `ORD-AAAA-NNN`. |
| 9 | `ENUM` (lista permitida) | `INSERT INTO cita (fecha_hora_agendamiento, fecha_hora_laboratorio, estatus_asistencia, folio_orden) VALUES ('2026-09-01 09:00:00-06', '2026-09-03 08:00:00-06', 'REPROGRAMADA', 'ORD-2026-0001');` | Rechazo por valor fuera del `ENUM` | `ERROR: invalid input value for enum enum_estatus_asistencia: "REPROGRAMADA"` | Solo se permiten los 5 estados operativos definidos. |
| 10 | `CHECK` entre columnas | `INSERT INTO cita (fecha_hora_agendamiento, fecha_hora_laboratorio, folio_orden) VALUES ('2026-12-05 10:00:00-06', '2026-12-01 08:00:00-06', 'ORD-2026-9999');` | Rechazo por fecha de laboratorio menor a agendamiento | `ERROR: new row for relation "cita" violates check constraint "chk_fechas_coherentes"` | La toma de muestra no puede ser anterior al registro de la cita. |
